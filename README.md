# 能让 AI Agent 陪玩 Galgame 的工具

## 怎么用

把下面这句话发给你平时用的 Agent，比如 DSH、Codex、Claude 或 Antigravity。使用能在你的 Windows 电脑上运行命令或连接本地 MCP 的客户端。

> 帮我部署 https://github.com/wonazhidao/galgame-agent-companion ，我想让你陪我玩《游戏名》。

部署好以后，你照常打开游戏，问它「能看到现在这句台词吗？」等它接上这一句，就可以边玩边聊了。你们可以一起猜角色在想什么、聊选项、分析剧情，也可以随口吐槽。

如果 Agent 说它看不到你的桌面，在**玩游戏的那台电脑**双击 **打开陪玩面板.bat**，从下拉列表点选游戏窗口，点 **开始陪玩**。再对 Agent 说「接上我在面板里选的游戏」。列表还提供最近玩过的游戏和已开启的会话。

## 原理

工具在本机找到游戏窗口，通过 Windows OCR 或可选的 Textractor 读取对白。Agent 能按顺序读到台词，支持图片的客户端还能看到当时的游戏画面。你可以直接在原来的聊天里接着聊。

## Agent 部署

在游戏所在的 Windows 10/11 电脑上克隆仓库。确认装有 Python 3.11，在仓库根目录运行 `.\安装依赖.bat --agent`。脚本创建独立虚拟环境并安装依赖。运行 `.\vn.cmd --help` 验证命令入口，然后根据客户端能力选择接入方式。手动安装也可以双击同一脚本。

- **能运行本地命令并查看图片的 Agent** 可以直接在此目录工作，操作说明在 `AGENTS.md`。这条路径装好依赖就能用。
- **支持本地 MCP stdio 的桌面 Agent** 可以注册一次陪玩工具，以后在其他工作目录也能按游戏名调用。在本目录打开 PowerShell，运行下方命令。把输出中的 `vn-companion` 条目合并进客户端的 `mcpServers`。如果客户端提供表单，传输方式选 stdio，并分别填写输出的 `command` 和 `args`。保存后按客户端要求重新连接。命令会按本机实际目录生成绝对路径；移动目录后需重新生成。

```powershell
.\vn.cmd mcp-config
```

连上后，Agent 可用 `list_game_sessions` 查找桌面面板已开启的会话，或用 `start_game` 开始候场。`read_game` 返回台词和本批 JPEG 拼图，客户端需要支持图片工具结果才能看图。

### 两个终端怎样接上

两个终端可以共用一场陪玩。采集器在游戏所在的交互式 Windows 桌面运行，Agent 从同一安装目录执行 `.\vn.cmd sessions`，拿到游戏名后执行 `.\vn.cmd wait "游戏名" --timeout 20`。如使用不同安装目录，请让两端的 `VNCOMPANION_HOME` 指向同一个有读写权限的本地目录。`.\vn.cmd doctor` 会显示实际目录和当前桌面；`on_input_desktop` 为 `null` 表示未能确认，读到游戏当前一句才算接上。

如果 Agent 在容器、WSL 或另一台电脑中运行，客户端需要能在游戏电脑上启动本地 MCP 服务，或调用该 Windows 目录里的命令。只有远端终端、也没有本机工具连接的客户端，无法直接访问你的游戏画面。

Windows OCR 使用系统已安装的识别语言。Textractor 为可选项。可把其含 x86、x64 的目录放在 `tools/Textractor`，或在第一次启动时传入 `--textractor "D:\Tools\Textractor"`。后台使用提取器自带的 CLI，并按目标程序位数选择版本。[Textractor 官方项目](https://github.com/Artikash/Textractor)

## 用游戏自己的回看核对台词

这份《素晴日》HD 中文版会把已播放的文字、角色名和文字片段写入 `UserData` 下的游戏存档。默认陪玩时，后台还会观察这些存档。游戏最小化时也能跟踪。首次连接只记住最近存档的位置；后续写入可对齐的存档时，Agent 的下一批内容会附上新增的**存档回看原文**。读取和确认沿用原来的批次机制。

- 想立即核对时，让 Agent “读一下最近存档的最后五条原文”。它可以调用 `review_game(kind="history", limit=5)`，或执行 `.\vn.cmd history "素晴日" --limit 5`。查询不会推进已读位置。存档里的无署名文字保留无署名。
- 只想使用游戏原文时，启动用 `.\vn.cmd start "素晴日" --mode history`，MCP 对应 `start_game(game="素晴日", mode="history")`。此模式等待游戏自己写存档。平时想逐句陪玩，用默认模式即可。
- 状态里的 `history.slot`、`history.entries`、`history.saved_ns` 表示最近读取的栏位、其中的回看条数及写入时间。玩家刚看见的对白可能比存档更新，实时截图也可能晚于存档中的某句话。系统不会自动操作存档。
- 读档后再次保存时，工具会比对两份历史里重合的记录；遇到回退或分歧会标出。没有可靠重合时，会提示重新定位，可手动查询该存档末尾。存档只保留有限历史，跨过整个窗口的部分无法从两份存档之间恢复。
- 同一次连接内，如果存档向前推进，工具会用两次存档观察之间实际采集的台词核对增量。至少两句具有辨识度的台词确定顺序后，中间能唯一定位的原句可显示为实时编号。相邻相同台词各自保留编号；存档新提供的署名附在对应编号后。漏采、位置存疑和读档分歧后的新增文字均以存档原文交付。

目前存档适配只用于已核对 SHA-256 的 `BGI-CHS.exe` 构建。它按存档内的署名和正文位置取值；未验证的版本继续使用原有采集路径。SDC 和 DCFS 容器格式参考 [Ethornell 的 SDC 实现](https://github.com/xmoezzz/ethornell-rs/blob/0bc6d1c0d5b662acc9006be94896324600ad05f1/crates/ethornell-vm/src/user_data.rs) 和 [DCFS 实现](https://github.com/xmoezzz/ethornell-rs/blob/0bc6d1c0d5b662acc9006be94896324600ad05f1/crates/ethornell-vm/src/records.rs)。

## 陪玩会话

在本目录的 PowerShell 中运行：

```powershell
.\vn.cmd start "天使们的约定"
.\vn.cmd status "天使们的约定"
.\vn.cmd wait "天使们的约定" --timeout 20
.\vn.cmd review "天使们的约定"
.\vn.cmd stop "天使们的约定"
```

- `start` 在后台创建会话，同名会话可重复启动。“等待游戏”表示可以打开游戏。“已找到窗口”表示匹配成功，“已取得画面”表示已截到窗口，“已读到文字”会附上实际样例。关闭游戏后会话继续等待，直到 `stop`。
- 面板的下拉列表可以直接选择已打开的窗口。还没开游戏时，可以选最近玩过的游戏、手填名字候场或浏览程序。有多个匹配窗口时，命令行也能用 `vn.cmd window "游戏名" 窗口编号` 选择。调整启动选项前先结束该游戏会话。
- 对已识别的游戏程序，后台尝试启动命令行提取器，并用 OCR 可见文字比对候选文本。来源有歧义时，用 `status.candidates` 显示的样句核对，再用 `vn.cmd choose "游戏名" 编号` 记住选择。未确认的来源可以继续用 OCR 跟读。已有 Textractor 在运行时，开发版使用 OCR。
- OCR 默认观察窗口下方的字幕区。全屏文字或竖排布局可用 `start "游戏名" --language ja --region 0,0,1,1`。四个数依次是左、上、右、下边界比例。也可指定 `--mode ocr`。OCR 对逐字显示会等文字稳定，快于采样的台词、字体识别错误和某些全屏渲染仍可能造成遗漏。
- `read` 取最早未确认的一批台词、消息和画面路径。`wait` 等待新内容。首次实时台词和玩家留言会立即唤醒等待。安静跟读用 `ack "游戏名" --batch 批号`，需要在面板回应时用 `reply "游戏名" --batch 批号 --title "标题" --body "正文"`。MCP 对应 `ack_game` 和 `reply_game`。
- 普通拼图合并相邻且像素完全相同的采样，在同一格标出起止时间和台词编号。画面中的 # 表示截图时已采集到的最后一句。用 `dialogue "游戏名" --start 42 --limit 1` 或 `review_game(game, kind="dialogue", start=42, limit=1)` 可回查该编号的实时原句，已读位置保持在原处。
- `review` 将最近六秒的画面拼图和同期台词加入待读内容。如果当时没有缓存画面，但窗口仍可截图，会附上当前帧并注明。`note "游戏名" "玩家的话"` 会把消息交给 Agent。关闭面板可继续后台陪玩。
- 每个游戏的设置、台词、截图和读取进度保存在本目录的 `sessions` 下。旧版游戏记录使用原来的目录。首次在开发版玩某款游戏时，会建立独立进度。

## 已验证的范围

使用屏幕外的模拟视觉小说窗口实测了按名称候场、真实 Windows 窗口截图、OCR 连读两句、批次确认、回看和关闭游戏后的重新候场。内置《素晴日》中文补丁字形映射及《天使们的约定》识别提示，其他窗口式单机视觉小说可以直接按名称试用。游戏引擎与汉化补丁的实际兼容性需要分别验证。

另用 240 条模拟采集记录验证了快翻时的交付顺序。Agent 读第一批期间追加了后 236 条，最终逐条核对，包含相邻的重复台词。此项覆盖台词进入日志后的交付；只在两次 OCR 采样之间出现的字幕仍可能漏采。

可用 `.\.venv\Scripts\python.exe -B bench_delivery.py` 在临时会话回放一段自造剧情，或加 `--source 旧版目录` 对比另一版。样本有 12 条存档原文、11 条实时台词、两位角色连续说出的同一句话、一条玩家消息和 12 帧画面。两批输出的正文从 1,614 字符减到 917 字符，按 `o200k_base` 分词从 1,122 减到 629 个 token。两张拼图分别从 1440×600 缩为 960×300。测量统一了临时路径和批号，仅统计新批次正文。图片、宿主上下文和模型回复的计费取决于实际客户端。运行环境装有 `tiktoken` 时脚本会给出分词结果。

在本目录运行以下命令，可验证面板、命令行和官方 MCP 客户端的 stdio 链路。测试会创建临时会话和独立的模拟游戏窗口，使用英语 OCR 语言包 `en-GB`。

```powershell
.\.venv\Scripts\python.exe -B -m unittest -v test_branch test_mcp test_history
```
